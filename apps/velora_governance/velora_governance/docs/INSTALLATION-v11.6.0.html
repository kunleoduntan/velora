Velora Governance v11.6.0 — Installation Guide

Version: 11.6.0 · Framework compatibility: Velora ≥1.19.0 and <1.20.0. Commands below use a typical Linux deployment layout. Confirm the exact app-install and migrate syntax with your installed Velora CLI help before executing, because CLI command names may differ between deployments.

1. Pre-install checklist

  • Take a database and file backup of the target company/site.
  • Confirm Velora Framework is within the supported version range.
  • Confirm Python/pip environment is the same one used by the Velora service.
  • Confirm company identifier and deployment path.
  • Install first in test/staging before production.

Application installation flow

The application installation itself follows the package deployment sequence: backup, stage the app source, register/install through the supported Velora CLI, migrate, restart, and qualify.

2. Discover the exact CLI syntax

velora --help
velora app --help
velora migrate --help
velora company --help

Use the help output to confirm the equivalent commands for app installation, migration, and company/site targeting.

3. Copy and unpack release bundle

# On the server, create a staging directory
mkdir -p /opt/velora/releases/governance-11.6.0
cd /opt/velora/releases/governance-11.6.0

# Copy the downloaded release bundle here, then:
unzip velora-governance-v11.6.0-release-bundle.zip
unzip velora-governance-v11.6.0-source.zip

# Inspect the extracted application
ls -la velora_governance
cat velora_governance/README-v11.6.0.md

4. Install source into the Velora apps directory

# Example app path — change to your actual Velora installation
sudo mkdir -p /opt/velora/apps
sudo cp -a velora_governance /opt/velora/apps/velora_governance

# Activate the Velora Python environment (example only)
source /opt/velora/venv/bin/activate
python -m pip install -e /opt/velora/apps/velora_governance

If your Velora deployment uses an app registry, app loader, Git checkout, or managed application installer instead of a Python editable install, use that deployment's supported mechanism. Do not install into a separate system Python.

5. Install app and migrate

# Confirm exact syntax first from: velora app --help
# Typical command pattern (use only if supported by your CLI):
velora app install velora_governance --company COMP-001

# Typical migration command pattern (verify help):
velora migrate --company COMP-001

Replace COMP-001 with the actual company/site identifier. Do not run a guessed command if your CLI help uses different syntax.

6. Restart services and verify

# Use your deployment's service names; examples only:
sudo systemctl restart velora-web
sudo systemctl restart velora-worker
sudo systemctl restart velora-scheduler

# Check service status (adjust names to actual units)
sudo systemctl status velora-web --no-pager
sudo systemctl status velora-worker --no-pager
sudo systemctl status velora-scheduler --no-pager
  • Open the Governance workspace and confirm the app shortcuts load.
  • Verify Governance roles are created and assigned.
  • Check Governance Automation Monitor.
  • Confirm exception centre, dashboard, export, print, and report pages.
  • Run staging UAT before enabling production scheduler activity.

7. Rollback plan

  1. Disable Governance scheduled jobs if a migration or runtime defect is found.
  2. Stop application services if required.
  3. Restore the database and files from the pre-install backup according to your Velora backup procedure.
  4. Remove/disable the app only through the supported Velora app lifecycle command; do not manually drop DocType tables.
  5. Record the defect and retain logs before retrying.
