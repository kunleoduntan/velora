VELORA RELEASE 0.42.0

Automated Backup Scheduling & Recovery Assurance

Configure repeatable backups across sites, companies and the control plane, verify their integrity, and retain a defined recovery history.

1. Configure a backup policy

velora ops configure --every-hours 24 --keep 14

Sets a 24-hour interval and retains the newest 14 backups per backup scope. Workspace snapshots and verification are enabled by default.

2. Protect the encryption password

export VELORA_BACKUP_PASSWORD='your-long-random-secret'

Use a host secret manager or a protected service environment. Never put the password in the policy JSON, audit log, source control or a world-readable crontab. Keep it separately from the backup files.

3. Run the scheduled operation

velora ops run-scheduled

The runner backs up configured site databases, the platform control-plane database and active company databases. If enabled, it also creates an encrypted workspace snapshot containing application, site, configuration and platform recovery material.

Use --force for a deliberate run outside the normal interval.

4. Let cron or systemd invoke Velora

0 * * * * cd /srv/velora && /usr/bin/velora ops run-scheduled >> /srv/velora/logs/backup-scheduler.log 2>&1

Invoke hourly; Velora itself checks the configured interval and avoids unnecessary runs. Ensure the scheduler process receives VELORA_BACKUP_PASSWORD securely.

5. Inspect results

velora ops backup-status
velora ops status

Review logs/backup-audit.jsonl for per-target results. A partial run means some targets succeeded while others failed. Failures do not advance the last-success timestamp, so the next invocation retries.

6. Understand verification boundaries

  • All database backup files are checked for gzip integrity.
  • SQLite backups additionally run PRAGMA integrity_check.
  • PostgreSQL dump verification is not a restore test. Restore into an isolated PostgreSQL instance before production approval.
  • Automatic destructive restore is intentionally not part of this scheduler.

For platform mode, keep encrypted workspace snapshots enabled. The platform configuration and master key are needed to recover encrypted company database credentials.
