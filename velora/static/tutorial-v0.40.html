Release 0.40.0

Enterprise Platform Readiness

Inspect workspace configuration and create a credential-free SHA-256 deployment inventory before and after deployment.

1. Run a readiness inspection

The inspection checks workspace structure, registered applications, site configuration, database configuration shape, file permissions, disk capacity and operational directories. It does not connect to tenant databases or change data.

velora readiness

Exit code 1 means at least one failed structural check. Warnings are reported separately.

2. Create a deployment manifest

The manifest records framework version, installed workspace app versions, relative source paths, file sizes and SHA-256 hashes. Site configuration, control-plane credentials, master keys, environment files and database files are excluded.

velora manifest create

Default output: config/deployment-manifest.json. An optional path can be supplied.

3. Verify deployed source

velora manifest verify

The verifier reports missing or changed files and rejects path traversal and symlink paths. Verification is read-only.

4. Recommended deployment sequence

  1. Run velora doctor and velora readiness.
  2. Take database backups and separately protect platform/master.key.
  3. Create and retain the source deployment manifest.
  4. Deploy through velora update and its migration/rollback workflow.
  5. Verify the deployed source with velora manifest verify.
  6. Run doctor checks and controlled login/transaction smoke tests.
  7. Schedule restore drills; a backup that has never been restored is not proven recoverable.

5. Security boundary

A manifest is an integrity inventory, not a digital signature. It cannot prove who produced the release. Protect the manifest through a trusted release channel or use signed attestations where authenticity is required. Readiness checks do not replace TLS/proxy review, monitoring checks, database connectivity tests, or application-specific validation.
