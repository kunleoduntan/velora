Velora v0.35.0

Enterprise User Administration UI & API

Manage central identities, company memberships and user sessions from a platform-administrator console.

1. Release objective

v0.35 connects the v0.34 identity lifecycle service to secured FastAPI endpoints and a browser-based administration page. The control plane continues to store identity and routing metadata only; business transactions and company-local permissions remain in each company database.

2. Open the administration page

Run Velora in platform mode and sign in using an account with platform-administrator privileges. Open:

https://your-velora-host/platform/users/manage

The page is served by the platform API and uses the existing HttpOnly velora_session cookie. It does not store the session token in browser local storage.

3. Available operations

  • Directory: search by email/name and filter active users.
  • Create user: new accounts default to inactive. Activate only after the approved onboarding process.
  • Edit profile: update email and display name with uniqueness and validation checks.
  • Activate/suspend: suspension revokes the user's active sessions.
  • Company memberships: grant/update company membership and role labels, or revoke a membership.
  • Sessions: inspect session metadata and revoke all sessions for a user.

4. API reference

  • GET /api/platform/users?q=&include_inactive=true
  • POST /api/platform/users — email, full_name, activate
  • PATCH /api/platform/users/{user_id} — email and/or full_name
  • POST /api/platform/users/{user_id}/status — active boolean
  • GET /api/platform/users/{user_id}/memberships
  • POST /api/platform/users/{user_id}/memberships — company_id and roles array
  • DELETE /api/platform/users/{user_id}/memberships/{company_id}
  • GET /api/platform/users/{user_id}/sessions
  • DELETE /api/platform/users/{user_id}/sessions — revoke all sessions
  • GET /api/platform/companies — company selector data

5. Security model

  • Every route requires a valid control-plane session and platform-administrator status.
  • Cookie-authenticated mutations require X-Velora-Request: 1.
  • Session listings omit token material and token hashes.
  • User suspension revokes sessions.
  • Memberships are company-specific; a membership does not itself grant DocType or business-record permissions.
  • All lifecycle mutations are written to the platform audit trail.

Do not enable immediate activation for an account until the identity proofing and credential delivery process is in place. Newly provisioned users receive no disclosed password from this API.

6. Validation and known limits

Targeted regression tests: 34 passed. Python compilation: passed.

The complete repository suite and production frontend build have not yet been completed. The current membership dialog is intentionally lightweight; SCIM, provider profile synchronization, federated logout and richer role-selection controls remain outstanding.
