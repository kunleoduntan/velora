Velora v0.43.0

Enterprise Monitoring & Recovery Assurance

Operational visibility and non-destructive database-backup rehearsal, extending the v0.42 automated backup foundation.

1. Check live database connectivity

velora ops monitor

Checks configured site databases and, where configured, the control-plane and active tenant databases. Results redact database URLs and credentials. Exit status is non-zero if a database probe fails.

2. Review backup freshness and RPO estimate

velora ops recovery-report

Reads the scheduler audit log, inventories local compressed backups and estimates the age of the latest successful scheduled run. A result of unknown means there is no successful audit evidence; stale means the last successful run exceeds the 26-hour default warning threshold.

3. Rehearse a SQLite backup safely

velora ops rehearse sites/demo.local/private/backups/backup-database.db.gz

Velora decompresses the backup into a temporary file and opens it read-only for SQLite PRAGMA integrity_check. It does not overwrite or connect to the live database.

4. PostgreSQL limitation

PostgreSQL plain SQL backups receive gzip and dump-signature preflight only. This command does not create a disposable PostgreSQL database or execute SQL. For a real rehearsal, provision an isolated database and restore with psql --set ON_ERROR_STOP=1, then validate application-level invariants.

5. Operational interpretation

  • Database monitor: connectivity now, not a guarantee of future availability.
  • Estimated RPO: age of latest successful scheduled audit entry, not proof that the backup restores.
  • Backup inventory: local files only; off-site copies are not discovered.
  • Dashboard and alert delivery: not included in this CLI milestone.

Command reference

velora ops monitor
velora ops recovery-report
velora ops rehearse /path/to/database-backup.gz
velora ops backup-status

Use a staging environment for restore tests. Never rehearse by restoring over a production database.
