Velora v0.27 — Security, Identity & Access Control

This tutorial introduces the SQLite-backed security engine: users, roles, company grants, DocType permissions, field access, sessions, API tokens and audit events.

1. Create the security manager

from pathlib import Path
from velora.security import SecurityManager

security = SecurityManager(Path("platform") / "security.db")

2. Create a user and assign a role

security.create_role("Accounts User")
user = security.create_user(
    "accounts@example.com",
    "Accounts User",
    "Use-A-Long-Unique-Passphrase-2026"
)
security.assign_role(user["user_id"], "Accounts User")
security.grant_company(user["user_id"], "company_001")

3. Configure permissions

security.set_permission("Accounts User", "Sales Invoice", "read", True)
security.set_permission("Accounts User", "Sales Invoice", "write", False)
security.set_field_access("Accounts User", "Sales Invoice", "grand_total", "read_only")

4. Authenticate and resolve a session

login = security.authenticate(
    "accounts@example.com",
    "Use-A-Long-Unique-Passphrase-2026"
)
identity = security.resolve_session(login["token"])
# Store the token securely; never log it or put it in a URL.

5. Authorize every server-side action

allowed = security.authorize(
    user["user_id"], "company_001", "Sales Invoice", "read"
)
if not allowed:
    raise PermissionError("Not permitted")

6. Issue a scoped integration token

token = security.issue_api_token(
    user["user_id"], "Billing Integration", ["invoice:read"]
)
identity = security.verify_api_token(token["token"], "invoice:read")
security.revoke_api_token(token["token_id"])
Production boundary: v0.27 supplies security primitives and persistence. FastAPI authentication middleware, ControlPlane integration, MFA/SSO and administration screens remain separate integration work. Do not expose a production service using developer-header authentication.

7. Run tests

pytest -q tests/test_security_v027.py tests/test_app_admin_v026.py
