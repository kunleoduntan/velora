Welcome to Velora

Most software asks you to squeeze your business into its screens. Velora turns that around. You describe your business: the documents it keeps, the fields on them, who approves what, who may see which figure. Velora builds the forms, lists, reports, permissions, notifications and API from that description, and keeps every change in an audit trail.

That is a rare and generous way to build: one small, careful engine; a separate database for every company so that no business ever sees another's records; approvals drawn on screen rather than written into code; installation, upgrade, backup and recovery that an administrator can do from one command line. The ERP, the project suite and the administration suite you may be using are all simply apps on this foundation, and so is whatever you build next.

This manual takes you from the first install to extending the framework yourself. Take it one section at a time. You will find the framework is on your side.

Other guides on this server: Velora framework · VeloraERP · ProjectOne · Velora Admin. A guide opens only if that application is installed.

1What Velora is (and is not)

Velora is the engine and chassis. Your business apps are the cars.

The frameworkDocuments and their life cycle, forms and lists, permissions, reports, REST API, notifications, broadcasts, search, scheduler, background worker, workflows, dashboards, portals, installer, updater and backups. It knows nothing about insurance, hospitals or churches.
AppsEverything specific to a business: its DocTypes (record types), rules, workflows, reports and screens. Each app installs, updates and is removed on its own. VeloraERP is one such app; so is the small sample app made by the quickstart.
CompaniesEvery company is a separate business environment with its own database, apps, users' roles and files. Nothing is shared or copied between companies.

Technology in one paragraph

Python 3.10+, FastAPI and SQLAlchemy on the server; SQLite for trying things out and PostgreSQL 13+ for real use; a React and TypeScript single-page Desk (the browser interface) that is built once and shipped inside the Python package. Records are described by JSON files (DocTypes), in the same spirit as Frappe, and Velora can read Frappe DocType exports.

The five rules that keep it that way

  1. Framework independence: no industry logic in the core.
  2. Application independence: every app installs and upgrades on its own.
  3. Database independence: one database per company; a problem in one never touches another.
  4. Extension independence: you extend with hooks, client scripts and settings, never by editing framework files.
  5. Upgrade independence: framework and apps are versioned and migrated safely (backup first, automatic undo on failure).

2The 15-minute tour

From nothing to your own working app. Each step is one command or one click.

  1. Install. On a laptop: pip install velora then velora quickstart. On a server: sudo bash install.sh --email you@company.com. You get a signed-in system with a first company, notifications and search. If you give no password, one is generated and shown once. 
    velora quickstart my-erp --email you@company.com --company "Acme Ltd"
  2. Create your app. 
    velora new-app inventory
velora new-doctype "Stock Item" --app inventory
velora new-doctype "Stock Item Line" --app inventory --child
velora new-doctype "Stock Movement" --app inventory --submittable
    This writes apps/inventory/ with a DocType definition (a JSON file), a controller and a client script for each record type.
  3. Describe your record. Open stock_item.json and list its fields, or paste a definition into the Desk's DocType Creator. Velora understands Frappe exports.
  4. Install it. 
    velora install-app inventory
velora --company COMP-001 install-app inventory
    The first command installs on every company, the second only on the selected one.
  5. Make the form yours. Open any form, press Customize form, drag fields, resize them, add sections and tabs.
  6. Add a notification. Create a Notification Rule: when a Stock Item changes and quantity is below 5, tell the Store Manager role by In-App and Email.
  7. Find anything. Press Ctrl+K and type part of a name. Accents and small typos are forgiven. Open the Shortcut Hub to search every record type and screen and pin favourites.
  8. Give the company its own address. 
    sudo velora domain add erp.yourcompany.com COMP-001

Later, sudo velora update keeps everything current and velora uninstall-app inventory removes the app after a backup.

3The ideas you need

IdeaWhat it is
WorkspaceThe folder Velora lives in: apps, settings, keys, files, backups. On a server: /srv/velora/workspace.
Control planeThe small registry that knows the users, tenants, companies, which database each company uses and which web address opens which company. It never holds business records.
TenantA group (for example a business group) that owns companies.
CompanyAn independent business with its own database. One login can reach several companies with a different role in each.
AppA folder of DocTypes, code and settings with a hooks.py. Different companies can have different apps.
DocTypeA kind of record defined by a JSON file: fields, permissions, naming, behaviour. Velora builds the table, API, list and form from it.
DocumentOne record. A submittable document goes Draft, Submitted (locked), Cancelled. A submitted document is never edited; to fix it you cancel it and amend it (a new draft linked to the cancelled one), or duplicate it.
Child tableRows that live inside a document (invoice lines). Declared as a DocType with the child flag.
RoleWhat a user may do with each DocType: read, write, create, delete, submit, cancel, amend, report, export, import, share, print, email. Roles are per company.
HookA place in hooks.py where an app plugs in: document events, scheduled jobs, lifecycle steps, route providers, portal providers.
Rule / WorkflowDeclarative behaviour stored in the company database: notification rules, approval workflows, dashboards, print formats.
WorkerThe background process (inside the server by default) that sends notifications, runs scheduler events and durable jobs.
Why one database per company? It is the strongest isolation there is. A failed upgrade, a restore, a slow report or a mistake in Company A cannot reach Company B. You can back up, restore, move or archive one company without touching the others. Companies in a group relate only through group administration, reporting and explicit intercompany transactions, never by sharing records.

5Installing, updating and removing

Where it runs

Python 3.10 or newer and PostgreSQL 13 or newer for a server. Ubuntu 22.04, 24.04, 26.04 and Debian 12 and 13 work with what they ship; Ubuntu 20.04 and Debian 11 work too (the installer fetches a private Python and the official PostgreSQL packages). SQLite is for trying things out.

Install on a server

sudo bash install.sh --email you@company.com
sudo velora doctor

It installs packages and PostgreSQL, creates a service user, the first company, one service (web + worker), the velora command and, optionally, nginx and HTTPS.

Update

sudo velora update

Order: new code, Python packages, backup, upgrade every company, new built-in features, restart. If any step fails everything is put back as it was. To update from your own GitHub repository see docs/install-from-github.md; apps can be pushed from the Desk (Publish to GitHub).

Preview an upgrade

velora upgrade --dry-run
velora upgrade-plan

Add and remove apps

sudo velora install-app velora_erp
sudo velora --company COMP-001 install-app velora_notify
sudo velora uninstall-app inventory           # data kept
sudo velora uninstall-app inventory --purge   # needs the backup

An app may declare required_apps, required_packages and required_velora (for example >=1.16.4,<1.16.4); the installer refuses to install when they are not met and refuses to uninstall an app another app depends on.

Remove everything

sudo bash uninstall.sh

A final backup is taken first; your data is kept unless you add --purge.

After every update run velora migrate (or simply velora update, which does it) so that new record types, account types and workspaces are created in each company.

6Where everything lives

One folder, six places. It can be moved, renamed, copied or restored anywhere and it still opens its own data.

FolderHolds
apps/Your code and installed apps. The only folder you edit or keep in version control.
config/Which apps are on, installation settings, a plain history of installs and updates.
platform/Sign-in, people, companies, the master key (keep it safe), one database file per SQLite company.
files/Attachments, one folder per company.
backups/Database and workspace backups.
logs/Server and worker logs.

Everything except apps/ is readable only by you, and the generated .gitignore means committing the folder can never publish a key or a database. velora layout shows it; velora layout --fix repairs it; velora start does that by itself. To back it all up use velora ops backup; on a new machine use velora ops restore-workspace BACKUP --into NEWFOLDER.

7Companies, tenants, users and domains

Create and manage

velora tenant create "Acme Group"
velora company create "Acme Nigeria Ltd" --tenant "Acme Group" --apps velora_erp,velora_notify
velora company list
velora user create boss@acme.com --name "The Boss"
velora user grant boss@acme.com COMP-001 --roles "System Manager"
velora company suspend COMP-002        # blocks access, deletes nothing
velora company activate COMP-002
sudo velora domain add erp.acme.com COMP-001 --primary

Passwords are never printed; give one with --password, the VELORA_USER_PASSWORD variable, or let it be generated. --unlocked on a domain lets people on that address reach their other companies too.

People and roles

A person signs in once. The control plane records which companies they may use and the roles they hold in each: Finance Manager in Company A, Accounts User in Company B. Roles live in the company database. The Desk offers user, role and permission administration, including module-level and DocType-level permission editors.

Single sign-on

The control plane includes an OpenID Connect client, federation, directory and SSO provisioning. Secrets are referred to by environment variable name, never stored in the database.

Domains

One company can have its own web address. velora domain check verifies DNS before the certificate is requested. In platform mode, public pages resolve only through an active domain mapping.

Groups and intercompany

Companies in the same tenant relate through group administration, consolidation reporting and explicit intercompany transactions. They never read each other's databases.

8Building an app

An app is a Python package under apps/.

apps/inventory/
  pyproject.toml
  inventory/
    __init__.py
    hooks.py
    stock/                      # a module
      doctype/stock_item/
        stock_item.json         # the definition
        stock_item.py           # controller (class StockItem(Document))
        stock_item.js           # client script (optional)
      report/low_stock/low_stock.json + low_stock.py

Velora finds DocTypes by scanning for doctype/<name>/<name>.json anywhere under the package. If a controller is missing, the plain Document behaviour is used. The class must be the PascalCase of the file name.

Document events, in order

insert  : permission(create) -> defaults -> before_insert -> naming -> before_validate -> validate -> before_save
          -> field checks -> DB write -> after_insert -> on_update -> after_save
save    : permission(write) -> row lock + optimistic-lock check -> before_validate -> validate -> before_save
          -> field checks -> DB write -> on_update -> after_save
submit  : permission(submit) -> docstatus=1 -> before_validate -> validate -> before_submit -> DB write
          -> on_update -> on_submit -> after_save
cancel  : permission(cancel) -> docstatus=2 -> before_cancel -> DB write -> on_update -> on_cancel -> after_save
delete  : permission(delete) -> before_delete -> link-integrity check -> DB delete -> after_delete

Everything in one event runs in one database transaction; any exception rolls the whole thing back. Each event runs the controller method first, then the handlers registered in doc_events.

A controller

from velora.document import Document
from velora.exceptions import ValidationError

class StockItem(Document):
    def validate(self):
        if (self.quantity or 0) < 0:
            raise ValidationError("Quantity cannot be negative")
        self.total = (self.quantity or 0) * (self.price or 0)

10Working with documents in Python

import velora

doc = velora.new_doc("Stock Item", item_name="Cable", quantity=10, price=1500)
doc.insert()

doc = velora.get_doc("Stock Item", "ITM-0001")
doc.quantity = 4
doc.save()

rows = velora.get_list("Stock Item", filters=[["quantity", "<", 5]], order_by="modified desc", limit=50)
n = velora.get_count("Stock Item", {"category": "Cables"})

order = velora.new_doc("Stock Movement", movement_date="2026-11-18")
order.append("lines", {"item": "ITM-0001", "qty": 3})
order.insert(); order.submit()
  • Filters are lists [["field","op",value]] or dictionaries.
  • Fields: get_list does not accept "*"; name the columns (registry.get(doctype).column_names() lists them).
  • Transactions: inside a request or document event you are already in one. A script or job that calls services directly wraps its work in with db.transaction():.
  • Permissions: calls made on behalf of a user enforce DocType, module and row-level permissions; internal code can run privileged.
  • Optimistic locking: saving a stale copy is refused, so two people never silently overwrite each other.
  • Submittable documents: submit(), cancel(), and an amend creates a new draft linked through amended_from. Cancel needs the cancel permission.
  • Linked documents: a document cannot be cancelled while another submitted document still points at it (through a Link field, in the document or in one of its child tables). The error names them. GET /api/linked-documents/{doctype}/{name} lists them and POST /api/cancel-all/{doctype}/{name} cancels the chain, newest first, in one transaction.
  • Things a document cleans up itself: a controller lists them in ignore_linked_doctypes = ("Payment", ...) so they do not block the cancel, and removes or unlinks them in on_cancel. An app that keeps links in plain fields (a source_doctype next to a source_document) supplies them through the hook linked_documents_provider (a module with dynamic_links(doctype, name)).
  • One cancel routine for every document: a hook doc_events = {"*": {"on_cancel": "app.module.function"}} runs for every document type. A DocType with "hide_from_menu": true is a system record, kept in the database but shown in no sidebar.

11The Desk, forms and the designers

The Desk is the browser interface: sidebar, list views, forms, reports, settings and centres.

Lists

Filter, sort, choose columns, group by, save filters, bulk actions (submit, cancel, delete, update field), export, import, and open a record with the keyboard. A list can have listview settings from a client script (indicators, extra columns).

Forms

Tabs, sections and columns; child-table grids with duplicate, move, drag and full-row edit; comments, attachments, tags, sharing, version history, copy ("duplicate"), amend, and the timeline of everything that happened to the record. Conditional fields (depends_on) are checked in the browser and enforced on the server.

Customize form (form designer)

A System Manager presses Customize form (#/settings/layout/<DocType>). A form can have a 12-column layout:

"layout": {"tabs": [{"label": "Details", "sections": [{"label": "Customer", "collapsible": false,
   "rows": [[{"field": "customer", "span": 6}, {"field": "posting_date", "span": 3}, {"field": "due_date", "span": 3}],
            [{"field": "items", "span": 12}]]}]}]}
  • A cell is one field with width 1–12; a row adds up to at most 12.
  • No field is ever lost: fields not in the layout go to a "More" section.
  • On a phone every cell is full width, so one layout serves both.
  • Save for everyone stores it for this company only; Save into the app (developer mode) writes it into the DocType JSON; Reset removes the company layout.
  • The designer has drag and drop, resize by edge, arrow keys, presets, sections, tabs, undo and redo.

Customize Form (settings page)

Settings → Customize Form (#/settings/customize-form, for administrators and designers) lists every DocType. For any field you can change the label, required, hidden, read-only, in list view and in the filter bar; Add field creates a custom field (any supported type) and puts it right after the field you choose (insert_after); a custom field can be removed again. Fields that ship with an app can be hidden but not deleted. Percent is not a field type: use Float.

Child-table grids

A child table opens with at most six columns (item, name, quantity, rate, amount, unit or warehouse and similar; fields flagged in_list_view come first, and bookkeeping fields such as source links never lead). Rows look like an Excel / Dynamics 365 sheet: thin grid lines, compact height, no zebra striping, a clear selected cell; Link cells are pink, currency cells light blue and data cells light yellow (tokens in the stylesheet, with dark-mode variants). A child row may have any number of fields; the grid shows the ones you choose and the row's edit button opens every field. The Columns button shows, hides, reorders and sizes columns: Save for me (this browser) or, for a System Manager, Save for everyone (or grid_columns in the child DocType).

Link fields: search like Frappe

Every Link field uses GET /api/search-link?doctype=&txt=&filters=: permission-aware, disabled records left out, the field's own filters applied, best match first (exact, starts with, title, contains) with a short description next to the ID. The old /api/search routes keep working.

Get Items From (copy and merge documents)

A draft document can fill its lines from other documents, as in ERPNext. The Desk shows a Get Items From button when the app can supply sources; a picker lists the documents that still have something open, you tick one or several, and their lines are added with a note of where each came from. The framework only provides the routes and the dialog; the app decides the rules through its document_flow_provider (hook), which may implement three optional methods:

GET  /api/pull-items/{target}/sources     -> provider.pull_sources(target)       list of source DocTypes
POST /api/pull-items/candidates           -> provider.pull_candidates(body)      {target, source, party, txt, exclude}
POST /api/pull-items/lines                -> provider.pull_items(body)           {target, source, names, party} -> {header, lines}

A provider that has none of them simply shows no button. VeloraERP implements them for Purchase Receipt, Purchase Invoice, Delivery Note and Sales Invoice (see the ERP manual).

Reports in the Desk

A report opens already run with its default filters. A Check filter is a tick box; switching it off is sent as an explicit false, so it never falls back to a default of “on”. The sheet has a header block, summary cards, right-aligned numbers, subtotal and total rows, Export to Excel and Print (menus are hidden when printing).

DocType Creator

#/settings/doctype-creator (developer mode and System Manager) or velora new-doctypes APP FILE --dry-run. It reads Velora's own format and Frappe DocType exports: field types, options, depends_on, fetch_from, permissions, naming, child tables and submittable flags are mapped; unsupported items are reported, not guessed.

12Client scripts

A .js file beside the DocType JSON is served by /api/client_script/<DocType> and runs in the form.

velora.ui.form.on("Investment", {
  refresh(frm) {
    if (frm.doc.docstatus === 1 && frm.doc.status === "Active") {
      frm.add_button("Accrue income", async () => {
        const r = await velora.api("POST", `/api/investments/${frm.doc.name}/accrue`, {});
        velora.msgprint("Accrued", "green");
        velora.reload();
      });
    }
  },
  validate(frm) {
    if (!frm.doc.counterparty) throw new Error("Counterparty is required");   // aborts the save
  }
});

15Workflows and approvals

Per-company workflow definitions drive approvals for any DocType. Approval is only ever a workflow: the framework has no built-in approval of its own.

The rule since 1.12.3. If no workflow is switched on for a DocType, its documents simply save and submit; nothing is blocked, and a Select approval_status left at Pending is settled automatically (velora.workflows.settle). When a workflow is on, it alone decides who may do what. A company that wants maker-checker ticks “the creator cannot approve” in the workflow itself.

Tutorial: draw a workflow in the builder

  1. Open Settings → Workflows and press New; choose the DocType.
  2. Under Start from pick a preset: One approver, Two levels, Parallel sign-off or By amount. The states and transitions appear as plain sentences (“from Draft, action Send for approval, to Pending Approval”).
  3. For each transition choose who may act: anyone, role chips (the list comes from GET /api/roles), or named people; choose the approval mode (single, any, all or a number of approvers).
  4. Add conditions (field, operator, value) so that, for example, only totals above a limit need the second approval, or add parallel groups that must all sign off.
  5. Check the automatic diagram and the problems list, switch the workflow on and save. Test it first with POST /api/workflows/{name}/simulate if you like.
  • Definition: DocType, initial state, states, optional state field, transitions (action, from, to, allowed roles or named users, conditions, approval policy).
  • Approval policy: single, any, all or quorum; conditions with all/any logic; parallel branches with their own approvers; delegations.
  • Versioning: definitions are immutable-versioned; each running instance keeps the version it started on; restore an old version as a new one.
  • Visual designer: drag states, draw transitions; transitions can run registered activities (notify, task, timer, sub-process, custom) and delayed activities use the job queue.
  • Inbox: GET /api/workflow-inbox lists what waits for the signed-in user; POST /api/workflows/{name}/simulate tests a definition.
  • Notifications: workflow events can fire notification rules.
Authority is configuration. The approval role authorises the state transition; it does not give general write access. Apps built on Velora (VeloraERP included) keep who-may-approve in settings, never hard-coded.

Sample workflows, approval policy and gaps

  • Samples. An app can ship sample workflows (hook workflow_template_provider, one module or a list). They install inactive: a company opens them in the designer, edits them and switches them on. Under Settings > Workflows > Sample approval workflows a System Manager can install any that are missing.
  • Policy decides, workflow routes. An app may hold a company's approval policy in its own settings and tell the framework through the hook approval_policy_provider (decide(doctype) returns True, False or None; workflow_changed(doctype, enabled) keeps the policy in step when someone switches a workflow on or off in the designer). True: approval is required. False: documents are approved on save. None: defer to whether a workflow is switched on.
  • No silent gaps. When policy requires approval but no workflow is active, submission is refused with a message naming the fix, and nothing can be approved by typing the status.
  • Setup Copy of settings. An app declares "settings": {"doctype", "fields", "tables"} in a Setup Copy section; the other company previews it ("N to update") and applies it. Links to records that do not exist there are skipped. A copied workflow replaces an unused inactive sample of the same name instead of colliding with it.
  • Create From. A document flow can declare a stage (submitted, draft or open) and ready conditions on fields, so follow-on actions appear for requests that are approved but not submitted.

17Importing and exporting data

Any DocType can be loaded from Excel and moved out again. In the Desk it is Excel only, and every child-table grid in a form has its own Import Excel and Export Excel buttons. The command line still reads CSV and JSON.

Honest limit. The SMS and WhatsApp request formats follow each provider's public documentation but were not run against the live services. Always press Send test first. Email was tested against a fake SMTP server and webhooks against a real local HTTP server.

Why it is reliable

  • Written with the document: notifications are created in the same transaction inside a savepoint, so none is lost on commit, none exists for a rolled-back change, and a broken rule can never make a save fail (it is logged under notify.errors).
  • Exactly once: idempotency key of rule + document + version + recipient + channel.
  • Outbox with retries: deliveries are sent by the worker outside any transaction; failure backs off 1 min, 5 min, 30 min, 2 h, 12 h, then Dead (visible; administrators can retry). A permanent error (bad address, not configured) is Dead at once.
  • Safe by construction: conditions run in a small interpreter (no eval), templates in Jinja's sandbox, email headers cannot be injected, webhooks cannot reach internal addresses.
  • Private: you see only your own notifications; the log and outbox are administrator-only.

From your own code

from velora_notify import trigger
trigger("Payment Failed", doc, key="attempt-3")     # fires Custom rules named "Payment Failed"; same key twice is a no-op

from velora_notify import channels
channels.register("Telegram", send)                  # send(delivery, settings); raise PermanentError for "never retry"

Limits

Quiet hours, digests (08:00) and "N days before" use the server's time zone. A rule cannot be attached to a child table (attach to the parent). Approve-by-link buttons are not built. At-least-once delivery means a rare duplicate if the process dies between sending and committing.

22Broadcast Centre

Send one message to many people by Email, SMS or WhatsApp, with delivery tracked per recipient. Screen: #/broadcasts. Record types: Broadcast, Message Template, Communication Opt-Out.

Send a broadcast in five steps

  1. Create a Broadcast: title, channel (Email, SMS or WhatsApp), optional Message Template, sender name, reply-to, CC and BCC.
  2. Write the message: subject, body (plain or HTML), optional video link. Personalise with {{ full_name }}, {{ salutation }}, {{ sender_name }}, {{ video_url }}, {{ unsubscribe_url }}.
  3. Choose the audience: A typed list (paste names and addresses or numbers), Records of a document type (pick a DocType, filters as JSON, and which fields hold the name, email, phone and salutation), or Both.
  4. Build recipients: Velora removes duplicates and opted-out people, drops invalid addresses or numbers and reports each reason. Inspect the preview of one personalised message.
  5. Test, then send: Send test goes to the test address and reports the real result; Send now or Schedule for a date and time. A send rate per minute spreads the load. Cancel stops what has not been sent.

Statuses

Draft, Scheduled, Sending, Sent, Partly Sent, Cancelled. Counters: total, queued, sent, failed, skipped, opted-out. Recipients carry their own status; Sync refreshes counters from the delivery outbox.

Opt-out and unsubscribe

  • Every email can carry a signed one-click unsubscribe link and a List-Unsubscribe header.
  • The unsubscribe page needs no sign-in (a public action). A link merely opened by a mail scanner does not unsubscribe anyone; the person must confirm.
  • Opted-out addresses and numbers go on the Communication Opt-Out list and are skipped in future broadcasts of that channel. You can add or remove entries manually.

Images and attachments

Pictures attached to a broadcast show inside an HTML email; other files are attached. Attachments use the file store.

API

23Security, roles and permissions

Design principle

Security is as simple as it can be and enforced on the server. Nothing the browser hides is the only protection.

LayerWhat it does
AuthenticationSign-in through the control plane (password with hashing and throttling, or SSO/OIDC). Developer-mode header authentication is refused outside developer mode.
Company isolationA request is bound to one company database; a user without a role in that company cannot reach it. A tenant security boundary stops credentials of one tenant being used on another.
RolesPer company. A DocType lists which roles may read, write, create, delete, submit, cancel, amend, report, export, import, share, print, email. The Desk also has module-level and DocType-level permission editors.
Row-level securityPolicies per role, DocType and permission with structured conditions (equals_user, eq, ne, in, not_in, is_set, is_not_set, in_user_roles). Conditions combine with AND within a policy, OR across roles; no raw SQL.
Field rulesmandatory_depends_on and validation are enforced on the server.
API credentialsCompany-local keys, shown once, stored hashed, scoped, expiring, never inheriting a person's roles.
SecretsOnly referred to by environment-variable name in settings; webhook secrets are encrypted with Fernet.
AuditVersion history on documents, export and import logs, platform audit trail (velora platform audit), activity log, and event log.
Outbound safetyWebhooks and gateways must be https and cannot target private addresses unless explicitly allowed.

Setting permissions in practice

  1. Create roles that match jobs, not people (Accounts Officer, Store Keeper).
  2. For each DocType in the Desk's permission editor tick what the role may do; submit and cancel are separate rights.
  3. Grant roles to people per company (velora user grant or the Desk user admin).
  4. Where users must see only their own rows, add a row policy.
  5. Sign in as a test user to confirm, and review the audit trail.
Hosting: read docs/hosting.md first. Do not expose a developer-mode server to the internet.

24PostgreSQL, SQLite and the database layer

Everything works on both; rules are always enforced in Python and, on PostgreSQL, also by the database.

  • Money is exact decimal (21 digits, 6 places).
  • JSON columns are JSONB on PostgreSQL; mark a field "json_index": true for a GIN index; filters json_contains and json_has_key.
  • Ledger protection (financial apps): append-only triggers, deferred balance checks, non-overlapping fiscal years, BRIN and covering indexes.
  • Search uses pg_trgm and unaccent when present.
  • Reports gain count_distinct, per-measure filters, median, percentile, stddev, rollup subtotals and gap_fill time series.
  • Apps add database objects with pg_objects in hooks.py (idempotent statements, allowed extensions: pg_trgm, unaccent, btree_gist, citext, pgcrypto, hstore, tablefunc, pg_stat_statements).
velora pg                 # version, extensions, rules applied, largest tables, advice
velora pg optimize        # apply the safe improvements
velora doctor
Before go-live turn on WAL archiving (or use pgBackRest) so you can recover to a point in time. Replication, TLS and tuning are for your host or DBA; Velora reports and advises. Mind the connection budget: see docs/connections.md.

26The Server Console: files, database and SQL

For platform administrators. Company Administration → Server Console lets you see and edit the server's files, browse the database and run SQL from the Desk, with the safeguards a production server needs.

Unlocking

Reading is free. Anything that changes framework or installed-app code, or changes data, first asks for your password again (and your authenticator code if you use one). The unlock lasts ten minutes, belongs to that one browser session and cannot be copied to another. Five wrong passwords lock the unlock for ten minutes. Every unlock, failed attempt, file edit and SQL statement is written to the audit log.

Files

FolderWhat it holdsAllowed
appsApps in this workspaceRead, edit, upload, copy, rename, delete
filesUploaded attachmentsRead, edit, upload, copy, rename, delete

  • You can paste new content into the editor, upload a file over an existing one (tick replace), or use Save a copy as and Copy to duplicate a file. Copies never replace an existing name.
  • A .py file with a syntax error or a .json file that does not parse is refused, so a typo cannot stop the server.
  • Before a file is replaced or deleted, the old version is kept in backups/file-history (the newest 25 per file). Earlier versions in the editor restores one.
  • Editing framework or app code changes files on disk; restart the service afterwards for it to take effect. Files that look like secrets (keys, passwords, .env) are never listed or opened, and symbolic links are never followed.

Database and SQL

  1. Choose a company, then a table to see its columns, key and rows (50 a page).
  2. Run a SELECT. It runs in a read-only transaction with a 15-second limit and shows at most 500 rows.
  3. To change data, write the statement and choose Preview changes. It is executed and rolled back, and you see how many rows it would touch. Only that exact statement can then be applied, after an automatic backup of the company.
  4. To remove rows, tick them in the table and choose Prepare delete; it writes the DELETE for you to preview.
Always one statement at a time. Statements that reach outside the company's own data (attach, copy, extensions, roles, grants, reading server files, server settings) are refused. On SQLite a schema change (CREATE, ALTER, DROP) cannot be previewed.

A stuck document

Type the document type and name, choose Mark as cancelled, Reopen as draft or Delete, and preview. Delete removes the document with its table rows. You must type the document's name to confirm, and a backup is made first. Postings and links made from the document are not reversed, so use this to clear a stuck record, not to correct accounts: cancel and amend properly whenever the document allows it.

Switching it off

Set VELORA_SERVER_CONSOLE=off in the service's environment and every console action, including file edits, is refused.

27Packaging, marketplace and AI tooling

  • App packages: velora validate-app checks a package without running its code, velora export-app builds a hash-verified ZIP, velora import-app-package imports it (rejecting unsafe archives) and velora marketplace manages trusted local repositories with SHA-256 checks.
  • Optional packages: velora deps lists and installs by name (PDF, QR codes, data analysis, SFTP, machine learning).
  • AI advisors: apps declare read-only advisors (ai_advisors hook) that the AI gateway can consult with provider settings. No advisor executes business actions.
  • AI Developer Studio and app builder: describe a record type or small app and get proposed DocTypes and migrations to review before anything is applied.
  • Application builder API and Studio help create apps and DocTypes from the Desk in developer mode.
Treat AI-generated definitions like any contribution: validate, read, test, then install.

28When something is wrong

SymptomLikely cause and fix
New record types or workspaces missing after an updateRun velora migrate for each company (or velora update).
"must define class SomeName" when loading a DocTypeThe controller class must be the PascalCase of the file name; with acronyms (SLA) delete the controller to use plain Document behaviour.
"No active transaction"A script or job called a service outside a request; wrap it in with db.transaction():.
Form button or list script not appearing after installThe .js or doctype JSON was not packaged: add them to package-data in pyproject.toml and rebuild.
Duplicate operation id error in testsOne function registered for GET and POST; register two routes with different operation ids.
Workspace shortcut rejectedThe route is not in the allowed pattern; use a known centre route or extend the pattern.
Emails or SMS not arrivingOpen the Notification Delivery list: Retry shows backoff, Dead shows the reason. Check the worker is running (velora doctor) and use Send test.
Server returns 503 and shows "upgrading"Maintenance mode is on (an update is running or it was set with velora maintenance on); turn it off with velora maintenance off.
Import rejects rowsRun with --dry-run --report failed.csv, fix the listed lines, re-import.
Database slots run outSee docs/connections.md for the PostgreSQL connection budget.

Start with velora doctor; it names what is wrong and how to fix it.

What is new in 1.19.2 (and everything since 1.16.4)

  • Company Administration (1.19.2): creating or duplicating a company with apps that need each other (VeloraERP and ProjectOne) works in any order. Duplicate company copies the setup sections you tick (chart of accounts, masters, workflows, permissions, finance policy), parents first and all or nothing; if the copy fails the new company is removed again. Grant access checks every role in every company first and grants nothing if one is wrong. Copying setup and Data Import are about 3.5 times faster: the scripts, automations, workflows and permissions of a DocType are read once per import instead of once per record and event (inside permissions.memoized()).
  • Update Centre (1.19.1): a new first step checks every wheel and runs the command line once before maintenance mode goes on, so a bad update changes nothing. pip runs offline (--no-index). Apps already installed are upgraded, not re-installed; only an app new in the update is installed, and the server restarts once, at the end. The worker no longer depends on python -m velora.
  • Publish on top of GitHub (1.19.1): if the repository already has commits this copy does not (a README created on GitHub, an earlier push from your computer), a plain push is refused. Publish on top of GitHub… lists the files that would be added, changed and removed, and on Yes adds one commit after the repository's own history. Nothing is ever force-pushed.
  • Install / Update from GitHub (1.19.1): on an app profile, one button brings the app from the repository (using the saved token, so private repositories work) and installs it in the profile's company. A new app is cloned; an existing one only moves forward. Local changes on the server, or histories that have gone different ways, stop it with an explanation. The restart command in update.restart_command is run if configured; otherwise restart the server, and databases upgrade themselves at start with a backup. To install an app that is not on the server yet, create an app profile and tick The app is only on GitHub so far.
  • Errors that help (1.19.0): an error answer carries advice: {"hint", "actions": [{"label", "href"}], "field"}. Raise it yourself with velora.throw(message, advice={...}), or let rules supply it: the framework has rules for missing fields, missing links, permissions, duplicates, stale edits and cancelled or submitted documents; an app adds its own with the hook error_advice (a module with RULES = [{"pattern": regex, "hint": ..., "actions": [...]}]; named groups fill {name} and {name_q}). The Desk shows the hint, the buttons and Go to the field.
  • Notes that do not block (1.19.0): velora.warn(message, hint=..., actions=[...]) lets the work go through and returns the note with the answer (warnings); the Desk shows it as a dismissible note. Use it for what is worth knowing but must not stop anyone; keep throw for controls.
  • Built-in workflow state (1.19.0): every submittable DocType gets a hidden, read-only workflow_state field (like amended_from), so a workflow can gate any document without Customize Form. The simple designer prefers approval_status, then workflow_state, and never a business status such as Document Status; its Quick approval row builds a one- or two-step approval with self-approval prevented.
  • People & Access (1.19.0): /api/people (list, add in one step, change roles, remove) for the company you are in, allowed to a platform administrator or that company's System Manager. Roles are validated against the roles the company's DocTypes use, with suggestions; the last System Manager cannot be removed; an existing sign-in is never given a new password by a company administrator. Apps describe jobs with the hook access_profiles ({"Accountant": {"roles": [...], "description": ...}}).
  • Fixed: roles set from the platform user screen (1.19.0): granting or changing a person's roles there wrote only the control-plane index, which sign-in ignores once the company holds its own role row, so later changes had no effect and a removed person's roles came back when they were added again. Grants and removals now go to the company database.
  • Create From can open a form unsaved (1.18.0): a document-flow provider's create_document_from may return {"prefill": True, "doctype": ..., "values": {...}} instead of a saved document. The API answers with name: null and the values, and the Desk opens a new form filled with them, marked "Started from ...", so nothing is created until the user saves. VeloraERP uses this for the actions of a Fixed Asset.
  • No silent failures in workflows (1.18.0): an approval-policy or workflow-template provider that fails to load, or a running instance whose frozen definition cannot be read, is now logged (logger velora.workflows) instead of being skipped quietly.
  • App hubs (1.16.5): every installed app has a sectioned hub in the sidebar and every parent document type belongs to a named section (a test covers all of them). Customise a hub lets each person drag shortcuts and sections, add their own, hide built-ins and reset; it is kept per person and company in that browser.
  • Hub registration for a new area (1.17.8): an app area appears in the sidebar by adding one entry to frontend/src/hubs.ts (id, title, owns by app and module, optional section patterns and centres). Debt & Treasury and Tax Management are examples. A screen of your own is a route in router.ts plus a lazy component in App.tsx; a workspace shortcut may point to it once the route is allowed in application_workspaces.py (tax-centre and treasury-centre were added).
  • Printing (1.17.0): saved print formats render with a sandboxed Jinja2 engine, so formats designed in Frappe or ERPNext show their content instead of raw template text; private attributes, imports and the filesystem are blocked and a template that does not compile is refused at save time. PDF output keeps tables. Print from every document and list with the format designed for it.
  • Amount in words (1.17.5): money_in_words writes the amount in words (naira and kobo, dollars and cents, and a few other currencies; other currencies use their code).
  • Child rows added during validation (1.17.1): rows a DocType adds while it validates now get their parent link and name before saving, for insert, save and submit.
  • Registry safety (1.17.3): the registry proxy refuses attribute patching; a leaked test patch had caused “DocType does not exist” failures in full runs. Patch the Registry class in tests instead.
  • Passwords and users (1.16.x): one password standard for sign-in, change, reset and administrators; administrator-issued temporary passwords; Forgot password with a one-time link or an administrator-handled request; a two-table simple workflow designer.
  • Applications released on this framework: VeloraERP 2.106.1 with Tax Management, Tax Report Library and Debt & Treasury (see its manual), ProjectOne, Velora Admin, Governance and Farepoint.
